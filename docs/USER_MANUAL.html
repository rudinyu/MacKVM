MacKVM User Manual

1. Before you start

M5 Pro MacBook Pro
Use dist/arm64/MacKVM.app.
2019 Intel MacBook Pro
Use dist/x86_64/MacKVM.app.
  • Both Macs must run macOS 13 or later and share a trusted local network.
  • Install and run MacKVM on both Macs.
  • An external display is optional for pairing and remote input; it is needed only for DDC switching and cross-display pointer mapping.
First launch: local builds use an ad-hoc signature rather than an Apple Developer ID notarized signature. If macOS blocks the app, right-click MacKVM.app in Finder, choose Open, and confirm.

2. Install and launch

  1. Copy the matching architecture of MacKVM.app to /Applications.
  2. Open it. MacKVM appears in the Dock with a full control window and also provides a KVM/display-sharing icon in the menu bar.
  3. Open either the Dock window or the menu-bar icon to access controls.
  4. Optionally enable Launch MacKVM at Login.
  5. Login-item startup keeps the full window hidden so it does not steal focus; use the menu-bar icon or Dock to reopen it.

Build both versions on the M5 Pro when needed:

./scripts/build-app.sh --arch arm64
./scripts/build-app.sh --arch x86_64

Create and verify a DMG:

./scripts/package-dmg.sh --arch universal
./scripts/verify-release.sh --app dist/universal/MacKVM.app --arch universal
(cd dist && shasum -a 256 -c MacKVM-1.100.03-universal.dmg.sha256)

The DMG is built from a clean staging directory and produces a portable SHA-256 sidecar. Ad-hoc signing is for local testing; distribution requires Developer ID, hardened runtime, and Apple notarization.

3. Physical keyboard, mouse, and trackpad path (P0)

Important: HDMI carries video only. It does not upstream the MA270U USB hub to the 2019 Intel Mac. Connect the external keyboard and mouse to the M5 Pro directly or through the MA270U USB hub. The built-in keyboard, mouse, and trackpad on either Mac can still request control.
  1. Keep One keyboard on M5 Pro (USB-C) selected in Physical input path.
  2. This mode documents the external USB path; either Mac can request software control from its local keyboard, mouse, and trackpad, and either Mac can receive remote input.
  3. Select External USB switch (bidirectional) only after both Macs visibly see the external keyboard and mouse through a real physical USB switch.

4. MA270U and cable setup

ComputerRecommended connectionMacKVM preset
M5 Pro MacBook ProMA270U USB-C video/data/90 W portM5 / USB-C preset
2019 Intel MacBook ProHDMI 1 through a USB-C/Thunderbolt adapterIntel / HDMI preset
  1. Some MA270U firmware does not expose a DDC/CI toggle in the OSD; MacKVM uses its native bridge when macOS exposes the display.
  2. MacKVM uses native IOKit DDC/CI: IOAVService on Apple Silicon and IOI2C on Intel. No Homebrew helper is required.
  3. Select Detect DDC-capable displays on either Mac and choose the intended display explicitly. MacKVM stores its stable native selector instead of assuming display number 1.
  4. Choose M5 / USB-C preset on the M5 Pro and Intel / HDMI preset on the Intel Mac; the MA270U EDID mapping sends USB-C as VCP 19 (0x13) and HDMI 1 as VCP 17 (0x11). A fresh Intel install defaults its local route to HDMI 1; the preset repairs older saved USB-C preferences. Other monitor models use their own firmware mapping; run the diagnostic scan before relying on a new model.
  5. Use Show other Mac before starting control. On either Mac it starts the guarded keyboard, mouse, and trackpad hand-off when control prerequisites are ready; Share keyboard, mouse, and trackpad with [other Mac] remains the explicit equivalent. The receiver selects Allow unless seamless control was enabled for the paired peer. If native detection or switching fails, read DDC diagnostic, check the direct cable path, and use the OSD as a fallback. For a display-only route, use Return display to this Mac; the emergency shortcut or the receiver's Return keyboard, mouse, and trackpad to [M5 Mac] action restores the local route during control.

If the Intel Mac uses HDMI 2, select HDMI 2 consistently in both input pickers. The monitor and cable must expose DDC/CI; otherwise use the monitor OSD.

5. Native DDC diagnostic and mapping scan

The repository includes a standalone diagnostic program built against the same native bridge as MacKVM. Build the matching architecture on each Mac, or build a universal binary on the M5 Pro:

./scripts/build-ddc-diagnostic.sh --arch arm64
./scripts/build-ddc-diagnostic.sh --arch x86_64
./scripts/build-ddc-diagnostic.sh --arch universal

It reports the running and compiled architecture, Mac model, macOS build, EDID identity/checksum, native transport, and VCP 0x60 input state:

./dist/ddc-diagnostic-arm64 > arm64-ddc-report.txt 2>&1
./dist/ddc-diagnostic-x86_64 > x86_64-ddc-report.txt 2>&1

When a monitor accepts I2C writes but does not switch, opt in to the mapping scan:

./dist/ddc-diagnostic-universal --display 1 --scan-inputs \
  --values 15,16,17,18,19,27
Hardware warning: the scan temporarily changes the monitor input. Run it only when the display can safely switch and restore. Only accepted=yes readbacks are mapping evidence; the tool never changes the app mapping automatically. Ctrl-C or SIGTERM stops the candidate loop and attempts to restore the original value; SIGKILL cannot be restored. The tested MA270U uses USB-C VCP 19 (0x13) and HDMI 1 VCP 17 (0x11).

See the diagnostic tool guide and its source.

6. macOS permissions

Complete Local Network, Input Monitoring, and Accessibility in that order on both Macs.

  1. Open the menu-bar item and select Enable Local Network.
  2. Respond to the macOS prompt, then select I handled the macOS prompt.
  3. Select Request Input Monitoring and Request Accessibility, allowing each macOS prompt.
  4. After the required checklist is complete, select Enable beside Control request notifications if native notifications are desired.
  5. Returning from System Settings refreshes the checklist; you can also select Refresh setup status.

If a permission was previously denied, use its Settings button. The Local Network review link remains available because macOS does not expose a programmatic allow/deny result to MacKVM.

7. Discovery, pairing, and control

  1. Confirm both Macs show the other under Nearby Macs.
  2. Select Pair on one Mac.
  3. Compare the six-digit security code and the displayed peer names. The receiving Mac selects Accept only when the codes match; the initiating Mac selects Confirm code after comparing the same code.
  4. After both signed decisions complete, MacKVM automatically attempts to connect the encrypted session. If it remains idle, select Connect on a paired row.
  5. With the external keyboard and mouse connected to the M5 Pro, select Show other Mac or Share keyboard, mouse, and trackpad with [other Mac]. Both use the guarded display-first hand-off when control prerequisites are ready. A newly paired receiver automatically authorizes that pinned peer. To require a prompt every time, turn off Automatically allow control from this Mac under Paired device information; the receiver then selects Allow. With the menu closed, use the native Allow, Deny, or Review in MacKVM notification.

Either Mac can initiate. If the receiving Mac shows a macOS Firewall prompt, allow incoming connections there. If the initiator remains waiting, use Cancel pairing or Retry pairing after the firewall rule is allowed. Starting from the Intel Mac is a valid workaround when its inbound rule has not yet been approved; the protocol is not architecture-specific.

Review opens an explicit Allow/Deny dialog. Allow on a locked Mac requires macOS authentication. Expired notification actions cannot start a later request.

8. Device profiles and support information

After pairing, MacKVM stores each peer's friendly name, advertised Mac model, last authenticated connection time, and SHA-256 fingerprint of the pinned public key. New pairings enable seamless control automatically; the per-peer toggle can revoke it.

  1. Open Paired device information to view the profile.
  2. Edit the Friendly name field and select Save; the name survives relaunch.
  3. Select Copy support information when reporting an issue.
The report contains public version, OS, device, UUID, fingerprint, and connection-status data. It excludes private keys, passwords, credentials, and network endpoints.

9. Daily operation and safe return

  • Input is not suppressed until the receiver selects Allow, unless seamless control was enabled for that pinned peer.
  • Use Return keyboard, mouse, and trackpad to this Mac on the controller. To switch back from Intel, the receiver selects Return keyboard, mouse, and trackpad to [M5 Mac].
  • Emergency shortcut on the M5 Pro: Control-Option-Command-Escape. The global Control-Option-Command-K shortcut is for a manually selected monitor input: it toggles keyboard, mouse, and trackpad ownership without running automatic DDC switching, starts a request while idle, and returns input while controlling or receiving. Control-Option-Command-O follows the guarded Show other Mac route: it automatically switches the display before requesting keyboard, mouse, and trackpad control, or ends receiving and restores the controller's display and input.
  • The public Quartz path forwards trackpad movement, clicks, drags, secondary clicks, precise two-axis scrolling, and scroll phase and momentum. A shared trackpad acts as a pointing device, not a gesture surface: CGEvent publishes constructors for keyboard, mouse, and scroll wheel only, so no multi-touch gesture can be injected on the receiving Mac. Pinch, rotate, smart zoom, three- and four-finger swipes, Mission Control, App Exposé, and Launchpad all stay local to the controlling Mac. The pressure value on a click is carried, but the force-click stage transition is not, so Look Up and QuickLook do not activate on the receiver.
  • Network loss immediately returns input locally and releases held keys, mouse buttons, and trackpad state.
  • A peer reconnects with bounded 0/1/2/4…30-second backoff. Seamless authorization resumes control without another prompt; an opted-out peer requires fresh consent. Disconnect, Forget, and Quit clear reconnect intent.
  • A keyboard-layout mismatch is rejected before consent; a layout change during control safely ends remote input.

10. P2 hardware acceptance

Run this section on the actual 14-inch M5 Pro, 2019 16-inch Intel MacBook Pro, and BenQ MA270U. CI cannot emulate monitor DDC/CI, a physical USB switch, or macOS privacy prompts.
  1. Run arm64 on the M5 Pro and x86_64 on the Intel Mac; complete permissions and pair with matching codes.
  2. With the one-way external USB topology, verify both Macs can request control from their local keyboard, mouse, and trackpad, and that either Mac can receive it.
  3. If using a physical USB switch, verify both Macs see the devices before testing bidirectional control.
  4. Watch the MA270U OSD while testing USB-C and HDMI switching. Record DDC diagnostics and test manual OSD fallback.
  5. During control test Return keyboard, mouse, and trackpad to [M5 Mac], the emergency shortcut, network unplug/reconnect, and quitting; no key, mouse button, or trackpad gesture state may remain stuck.

11. Troubleshooting

The other Mac is not visible

Confirm both Macs share the same Wi-Fi or Ethernet network, MacKVM is running, and the Local Network setup step is complete. Guest or corporate networks may block Bonjour.

Control does not work

Confirm the controlling Mac has both Input Monitoring and Accessibility for its active event tap, the receiving Mac has Accessibility, both devices are paired, and the secure session shows connected. Pairing alone does not grant control: request control from either Mac's local keyboard, mouse, or trackpad, then select Allow on the receiver.

No control notification

Enable Control request notifications in the setup checklist and check System Settings → Notifications → MacKVM. When notifications are disabled, the request remains in the menu/window and the KVM icon shows a warning.

The monitor does not switch

Confirm the monitor and cable expose DDC/CI, select Detect DDC-capable displays, and read the DDC diagnostic if switching fails. Use the OSD manually when needed.

The identity or Keychain is inconsistent

Use Reset this Mac identity only when the old identity should be discarded. It removes local pairings; after relaunch both Macs must be paired again.

1. Before you start

M5 Pro MacBook Pro
Use dist/arm64/MacKVM.app.
2019 Intel MacBook Pro
Use dist/x86_64/MacKVM.app.
  • Both Macs must run macOS 13 or later and share a trusted local network.
  • Install and run MacKVM on both Macs.
  • Set the MA270U as the main display on both Macs.
First launch: local builds use an ad-hoc signature rather than an Apple Developer ID notarized signature. If macOS blocks the app, right-click MacKVM.app in Finder, choose Open, and confirm.

2. Install and launch

  1. Copy the matching architecture of MacKVM.app to /Applications.
  2. Open it. MacKVM does not appear in the Dock; it appears as a keyboard icon in the menu bar.
  3. Click the keyboard icon to open the MacKVM menu.
  4. Optionally enable Launch MacKVM at Login.

Build both versions on the M5 Pro when needed:

./scripts/build-app.sh --arch arm64
./scripts/build-app.sh --arch x86_64

Create and verify a DMG:

./scripts/package-dmg.sh --arch universal
./scripts/verify-release.sh --app dist/universal/MacKVM.app --arch universal
(cd dist && shasum -a 256 -c MacKVM-0.9.0-universal.dmg.sha256)

The DMG is built from a clean staging directory and produces a portable SHA-256 sidecar. Ad-hoc signing is for local testing; distribution requires Developer ID, hardened runtime, and Apple notarization.

3. Physical keyboard and mouse path (P0)

Important: HDMI carries video only. It does not upstream the MA270U USB hub to the 2019 Intel Mac. Connect the keyboard and mouse to the M5 Pro directly or through the MA270U USB hub.
  1. Keep One keyboard on M5 Pro (USB-C) selected in Physical input path.
  2. This mode lets the M5 Pro request control and keeps the Intel Mac receive-only; the Intel Mac can still receive remote input.
  3. Select External USB switch (bidirectional) only after both Macs visibly see the keyboard and mouse through a real physical USB switch.

4. MA270U and cable setup

ComputerRecommended connectionMacKVM preset
M5 Pro MacBook ProMA270U USB-C video/data/90 W portM5 / USB-C preset
2019 Intel MacBook ProHDMI 1 through a USB-C/Thunderbolt adapterIntel / HDMI preset
  1. Enable DDC/CI in the MA270U OSD if the option is available.
  2. MacKVM uses native IOKit DDC/CI: IOAVService on Apple Silicon and IOI2C on Intel. No Homebrew helper is required.
  3. Select Detect DDC-capable displays on either Mac and choose the intended display explicitly. MacKVM stores its stable native selector instead of assuming display number 1.
  4. Choose M5 / USB-C preset on the M5 Pro and Intel / HDMI preset on the Intel Mac; both can use automatic native DDC/CI.
  5. Use Show this Mac and Show other Mac before starting control. If DDC fails, read DDC diagnostic and use the OSD as a fallback.

If the Intel Mac uses HDMI 2, select HDMI 2 consistently in both input pickers. The monitor and cable must expose DDC/CI; otherwise use the monitor OSD.

5. macOS permissions

Complete Local Network, Input Monitoring, and Accessibility in that order on both Macs.

  1. Open the menu-bar item and select Enable Local Network.
  2. Respond to the macOS prompt, then select I handled the macOS prompt.
  3. Select Request Input Monitoring and Request Accessibility, allowing each macOS prompt.
  4. After the required checklist is complete, select Enable beside Control request notifications if native notifications are desired.
  5. Returning from System Settings refreshes the checklist; you can also select Refresh setup status.

If a permission was previously denied, use its Settings button. The Local Network review link remains available because macOS does not expose a programmatic allow/deny result to MacKVM.

6. Discovery, pairing, and control

  1. Confirm both Macs show the other under Nearby Macs.
  2. Select Pair on one Mac.
  3. Compare the six-digit security code and the displayed peer names, then select Accept on both Macs only when the codes match.
  4. Select Connect after pairing.
  5. On the controlling Mac select Request control of other Mac. The receiver must select Allow. With the menu closed, use the native Allow, Deny, or Review in MacKVM notification.

Review opens an explicit Allow/Deny dialog. Allow on a locked Mac requires macOS authentication. Expired notification actions cannot start a later request.

7. Device profiles and support information

After pairing, MacKVM stores each peer's friendly name, advertised Mac model, last authenticated connection time, and SHA-256 fingerprint of the pinned public key.

  1. Open Paired device information to view the profile.
  2. Edit the Friendly name field and select Save; the name survives relaunch.
  3. Select Copy support information when reporting an issue.
The report contains public version, OS, device, UUID, fingerprint, and connection-status data. It excludes private keys, passwords, credentials, and network endpoints.

8. Daily operation and safe return

  • Input is not suppressed until the receiver selects Allow.
  • Use Return input to this Mac on the controller or Stop remote control on the receiver to end control.
  • Emergency shortcut: Control-Option-Command-Escape.
  • Network loss immediately returns input locally and releases held keys and mouse buttons.
  • A peer reconnects with bounded 0/1/2/4…30-second backoff, but control consent is required again. Disconnect, Forget, and Quit clear reconnect intent.
  • A keyboard-layout mismatch is rejected before consent; a layout change during control safely ends remote input.

9. P2 hardware acceptance

Run this section on the actual 14-inch M5 Pro, 2019 16-inch Intel MacBook Pro, and BenQ MA270U. CI cannot emulate monitor DDC/CI, a physical USB switch, or macOS privacy prompts.
  1. Run arm64 on the M5 Pro and x86_64 on the Intel Mac; complete permissions and pair with matching codes.
  2. With the one-way topology, verify the M5 Pro can request control, the Intel Mac can receive it, and the Intel request button is disabled.
  3. If using a physical USB switch, verify both Macs see the devices before testing bidirectional control.
  4. Watch the MA270U OSD while testing USB-C and HDMI switching. Record DDC diagnostics and test manual OSD fallback.
  5. During control test Stop remote control, the emergency shortcut, network unplug/reconnect, and quitting; no key or mouse button may remain stuck.

10. Troubleshooting

The other Mac is not visible

Confirm both Macs share the same Wi-Fi or Ethernet network, MacKVM is running, and the Local Network setup step is complete. Guest or corporate networks may block Bonjour.

Control does not work

Confirm Input Monitoring and Accessibility are granted on the appropriate Macs, both devices are paired, and the secure session shows connected.

No control notification

Enable Control request notifications in the setup checklist and check System Settings → Notifications → MacKVM. When notifications are disabled, the request remains in the menu and the keyboard icon shows a warning.

The monitor does not switch

Confirm the monitor and cable expose DDC/CI, select Detect DDC-capable displays, and read the DDC diagnostic if switching fails. Use the OSD manually when needed.

The identity or Keychain is inconsistent

Use Reset this Mac identity only when the old identity should be discarded. It removes local pairings; after relaunch both Macs must be paired again.
